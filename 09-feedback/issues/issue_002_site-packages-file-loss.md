## 根因（每条都有实测证据，非推断）

## 规避与处置建议

1. **禁止**在本环境下对多文件大包执行 `pip uninstall` / `pip install --force-reinstall`：卸载 `opencv-python` 会连带删同命名空间的 `cv2`；卸载 `paddlepaddle`(CPU) 会删共享 `paddle/` 树，直接打死 `paddlepaddle-gpu`。
2. 修环境一律用**覆盖法**（`pip download` → 解压 → 只补缺失文件 → 覆盖写入；不删除），与本项目既有硬规则一致。
3. 必须批量删除时，**先把该命令超时放大到 ≥1800 s**，并在删除前建 cache-manager 快照；或对纯残留目录（如 `~umpy`）使用不经回收站删除的快速通道（实测 `cmd /c rd /s /q` 0.74 ms/文件），但会放弃"可撤销"能力，需用户拍板。
4. 恢复：5,186 个文件可从回收站按包逐个恢复；**不要盲目整体回灌**（旧版本文件混入新版本目录会二次损坏），应按包判断"整包缺失→从回收站恢复 / 部分缺失→用 wheel 覆盖法补齐"。
5. 保留本次开启的系统审计（File System 审核 + `C:\Program Files\Python313` 的 Delete SACL）→ 以后再发生同类事件可**直接拿到肇事进程名与时间**。
