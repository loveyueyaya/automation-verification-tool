   规划："统一保留 opencv-python，另外两个卸载"

     · paddlex 3.7.2 的 ocr-core/base 等 extra 硬性要求 `opencv-contrib-python==4.10.0.84`
     · 该判断读的是 **dist 元数据**（is_extra_available），不是 import —— 删掉该 dist-info 会让 PaddleOCR 直接拒绝创建流水线（已实测复现）
   最终状态：opencv-python 4.10.0.84 + opencv-contrib-python 4.10.0.84（同版本，无冲突）；opencv-python-headless 5.0.0.93 已移除（旧包备份在 F:\wordbuddy\2026-09-18-21-23-01\_backup_opencv_stale\）
   遗留：僵尸 opencv_python-5.0.0.93.dist-info 已于 09-19 清理完毕
2. 显存监控方案替换 —— ✅ 完成
   ocr.py 已改 pynvml 原生 API（含 Windows nvml.dll 预加载兼容段）；实测读 12282 MiB，21 ms/次（nvidia-smi 147 ms/次）
   补记：nvidia-ml-py3 7.352.0 的 dist-info 曾在事故中丢失，09-19 已从回收站原样恢复
3. BUG-1（区域截图失效）—— ✅ 已修

四、新增：环境硬规则（09-19 实测得出，所有轮次通用）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 禁止对大包执行 pip uninstall / pip install --force-reinstall
   实测：本环境删除经 genie-trash 逐个进回收站，47~126 ms/文件（cmd del 仅 0.74 ms/文件，慢 64~170 倍）
   → 数千文件的卸载必然超过命令超时被强杀 → 包被半删（回收站出现 ~umpy / ~addlepaddle-*.dist-info 等指纹）
   注：卸载 opencv-python 会连带删共享 cv2/；卸载 paddlepaddle(CPU) 会删共享 paddle/ 树打死 paddlepaddle-gpu
2. 修环境一律用「覆盖法」：pip download 取 wheel → 解压 → 只补缺失文件 → 覆盖写入（不删除）
3. 必须批量删除时：先把该条命令超时放大到 ≥1800 s，并先建 cache-manager 快照
4. 一切判断基于本机实跑：文件/包存在性用 os.path.exists / importlib.util.find_spec / 实跑验证，
   不得用 RECORD、README、索引描述替代实测（已出现"RECORD 说文件在、实际目录已空"的反例）
5. 用户提供的判断/状态同样要跑代码复验后再采信
6. 版本问题查官方手册与更新说明；不涉及本项目实际调用 API 则不做升级
7. 系统审计（File System 审核 + Python313 的 Delete SACL）长期保留，可归因删除进程
