## 三、环境事故与处置（v2 新增）

### 3.1 事故与根因（全链路实测，非推断）

**根因链**：工具层把命令触发的删除**逐个文件转送回收站**（`genie-trash\win32-x64.exe`，系统审计事件 4663 实证）→ 实测 **47~126 ms/文件**（对照 `cmd /c del` **0.74 ms/文件**，**慢 64~170 倍**）→ 大包 `pip uninstall` / `--force-reinstall`（数千文件）**必然超过命令超时**（180~600 s）→ **进程被强杀**（`killed=true` 28 次，时刻与删除潮末点精确重合）→ 卸载中断 → 包被"半删"（回收站留 `~umpy`、`~addlepaddle-3.3.1.dist-info` 等 `~pkg` 指纹）。

**已排除**（均实测）：磁盘空间、杀软隔离（系统未注册杀软、Defender cmdlet 不存在）、沙箱 GC（仅"无需删除"172 次）、CLI 文件树清单回滚（只覆盖工作区）、凭据检测规则。

### 3.2 损失评估（结论：**不恢复**）

| 维度 | 结论 |
|---|---|
| 项目源码树 | **零损伤**（P2-layers 16/16、tests 4/4 行数与基线一致；shot.py / ocr.py 差异为 BUG 修复） |
| 环境真实缺失 | 3,804 个，其中**核心文件仅 1 个**（`cv2\opencv_videoio_ffmpeg500_64.dll`，opencv 5.0 遗留）；其余 `.pyc` 3,220（自动重建）/空目录条目 571/`.pyi` 6/`.txt` 4 |
| 涉及包可导入性 | **44/44 全部可导入** |
| 恢复决策 | 不恢复（无可恢复功能缺口；回收站为旧版本，回灌有版本混杂风险；写入成本高） |

## 六、风险与硬规则（v2 新增，必须遵守）

1. **删除类操作禁令**：不在本环境对大包执行 `pip uninstall` / `pip install --force-reinstall`。卸载 `opencv-python` 会连带删共享 `cv2/`；卸载 `paddlepaddle`(CPU) 会删共享 `paddle/` 树打死 GPU 版。
2. **修环境一律用覆盖法**（`pip download` → 解压 → 只补缺失文件 → 覆盖写入，不删除）。
3. **必须批量删除时**：先把该条命令超时放大到 ≥1800 s，并先建 cache-manager 快照。
4. **一切判断基于实测**：文件/包存在性用 `os.path.exists` / `importlib.util.find_spec` / 实跑验证，不得用 RECORD、README、索引描述替代。
5. **审计保留**：系统文件系统审核 + `C:\Program Files\Python313` 的 Delete SACL 长期保留，可随时归因删除进程（回滚命令见 root-cause 报告 §2.3）。
6. **版本问题处理**：查官方手册/更新说明；不涉及本项目实际调用 API 则不做升级。
