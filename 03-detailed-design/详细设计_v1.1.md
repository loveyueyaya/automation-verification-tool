## 四、跨进程 trace 协议（落地版）

```
父进程 uitool.py
  ├─ spawn 前 记录 t_parent0
  ├─ 子进程 ocr.py --image x.png --trace-id <tid>        (或 UI_TRACE_ID=<tid>)
  ├─ 子进程入口 记录 t_child0；offset = t_parent0 - t_child0
  ├─ 子进程 span.ts = time.time() + offset（归一父时钟）
  └─ 全部写入同一 session 的 timeline.jsonl（不新建 session 目录）
     首行声明 {pid, parent_trace_id, clock_offset}
```

**字段契约（建议修 7）**：

```
record(ts, ts_source, src, conf, chain, action, result)        ← P1 现有字段（timeline.record）
record(ts, ts_source, span_id, parent_span, trace_id, src, conf, chain, action, result)  ← P2 扩展
```

- `span_id` / `parent_span` / `trace_id` = **P2 新增字段**
- P1 的 `contracts/models.py::TraceSpan` 现定义：`trace_id / layer / step / ts_start / ts_end / meta`（**无 span_id / parent_span**）
- **需要更新 models.py**：TraceSpan 增加 `span_id: str = ""`、`parent_span: str = ""`（默认值，向后兼容 P1 调用），P2 落 observability/logger.py 时同步生效

**报告展示**：offset 含子进程启动延迟 N ms → 展示行注明"子进程启动延迟 N ms 已计入偏移"。
**断链检测**：孤儿 span（无父）→ 标黄 + "跨进程断链"告警。
**落地锚点**：`uitool._sub()` 全部子进程调用加 `--trace-id`（约 6 处）。

## 五、幂等性分级表

| 等级 | 定义 | 动作示例 | 重试策略 |
|---|---|---|---|
| L0 | 天然幂等 | 查询、读状态、截图 | 可无限重试（同输入同输出） |
| L1 | 幂等（有副作用但可重复） | 设置开关、粘贴文本 | retries ≤ 2，成功后校验 |
| L2 | 条件幂等（依赖前置状态） | 点击按钮（前置=按钮存在） | retries ≤ 2 + 每步 light_check |
| L3 | 非幂等（不可安全重放） | 提交表单、转账类 | **禁止自动重试** → EXCEPTION / HUMAN 流 |

规则：
- L0/L1 失败 → NORMAL 流重试（backoff 200/800ms）
- L2 失败 → 重试前先 light_check（目标元素指纹 + 窗口 rect），失效则走 EXCEPTION
- L3 失败 → 直接 HUMAN 流（人工介入），retries 字段置位记录
