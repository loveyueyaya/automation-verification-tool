## 一、7 层 MVP 结构（横切不算层）

```
层1  编排         orchestrator/    任务/队列/窗口互斥锁/人工介入/trace_id
层2  环境适配     env_adapter/     探测→缓存→路由(注入/截图)→焦点→降级表
层3  感知         hardware+perception/
                  capture(路由后) + input(路由后) + dpi + resource_monitor
                  + window + uia + ocr_engine(单例) + element_detect + snapshot
层4  决策与缓存   state_cache+planner/
                  state_store + rule_cache + element_cache + decision_cache
                  + prompt_templates + flow_planner + exception_handler + llm_client
                  （decision_cache 默认降级为规则优先：缓存命中即出动作，LLM 仅异常/未命中）
层5  执行         locator+executor/
                  resolver + handle/uia/coord 匹配 + queue + action_runner
                  + retry_policy(幂等) + humanize
层6  校验         verifier/        state_diff + ocr_check + screenshot_diff + business_assert
层7  观测         observability/   logger + metrics + report + replay

横切（代码包，不参与分层）：
  contracts/    枚举/模型/错误码/校验器/版本
  regression/   三工具 smoke + 门禁
  config/       环境配置/阈值/性能预算表（yaml）
```

**合并理由**：层3 的 hardware 与 perception 共享同一引擎实例（截图引擎被路由后直接供感知用，拆开徒增接口层）；层4 决策与缓存合并后"缓存优先、LLM 兜底"成单一职责；层5 定位与执行合并后"意图→动作"一条线。7 层跑通后再按需拆细（拆点已注释）。

## 二、退化 1 修复：元素指纹三层可分解

```python
# contracts/models.py（设计规格）
ELEMENT_ID = "elem_s:{semantic_hash}_p:{control_path}_h:{handle}"
# 示例：elem_s:a3f2_p:Window/Edit[1]_h:0x1A2B

# 三层可分解 → 定位层按层回退：
#   L1 handle:      handle 命中 → 直接用
#   L2 control_path: handle 失效 → UIA 控件路径重定位
#   L3 semantic:    控件树失效 → 语义锚点（文本 + 相对位置）OCR/模板校验后定位
```

**规则**：
1. 三层各自独立可空：`elem_s:__p:__h:0x1A2B`（仅 handle）合法；缺层不拉垮其他层
2. id 反查：`split("_s:")/_p:/_h:` 解出三层，**优先用存在的最高优先级层**，逐层降级
3. 碰撞消歧：同 hash 同 path 不同 handle → 追加语义文本前缀消歧（`elem_s:a3f2_login_p:...`）；仍撞 → 取最新快照，触发二次校验
4. 禁止把三层揉成一个 sha1（v2 的错误已废弃）

## 三、退化 2 修复：state_hash 规范化规格

```python
def state_hash(s: StateSnapshot, target_hint: str) -> str:
    # 1) 关键元素选择规则（显式，非"与目标相关"这种模糊词）：
    #    参与字段 = [target_hint 指定的元素, 所有输入框, 所有按钮, 窗口标题, 活动窗口 rect 量化]
    #    规则：只取 type ∈ {button, input, text_area} 且 bbox 在窗口内 的元素；
    #          每类最多取 8 个；其余元素不参与哈希
    # 2) 位置量化容差：bbox 左上角量化到 2% 网格（x/窗口宽、y/窗口高 取 2% 格）
    # 3) 文本规范化：去首尾空白、全角→半角、统一小写
    # 4) 输出 = sha1(排序后的 "type:text_norm:cell_x:cell_y" 列表 + 窗口标题)
    ...
```

**碰撞后二次校验（非"命中即用"）**：缓存命中后，取命中元素的实时指纹（handle/控件路径）与缓存比对，任一失效 → 视为未命中，走完整流程。

**明确不参与哈希**：ocr 结果、visual_features、坐标原始值、trace 元数据（防止每帧抖动改 hash）。

## 四、退化 3 修复：跨进程 trace 传播

现有代码真实形态：`uitool.py` → 子进程 `ocr.py` / `sendinput.py` / `shot.py`。v2 默认单进程，子进程不传 trace_id 则 span 断链、报告无法回放。修复：

```python
# 1) 子进程入口统一接收 trace_id（两种方式二选一，环境变量优先）
#    CLI:  python ocr.py --image x.png --trace-id <tid>
#    ENV:  UI_TRACE_ID=<tid> python ocr.py ...
# 2) 日志协议：子进程写入同一 session 的 timeline.jsonl（不新建 session 目录）
#    首行声明 {pid, parent_trace_id, clock_offset}
# 3) 跨进程时间对齐：父进程在 spawn 前记录 t_parent0；
#    子进程记录 t_child0 = time.time()；偏移 offset = t_parent0 - t_child0
#    子进程 span 的 ts = time.time() + offset（全部归一到父进程时钟）
# 4) 断链检测：报告生成时校验"每个 span 的 trace_id 链完整"
#    孤儿 span（无父）→ 标黄并输出"跨进程断链"告警
```

**落地锚点**：现有 `uitool._sub()` 子进程调用全部加 `--trace-id`；`timeline.record` 增加 `parent_span` 字段。

## 五、采纳建议 3：执行流切换代码化

```python
# orchestrator/flow.py
def select_flow(state: StateSnapshot, cache_hit: bool,
                diff: StateDiff | None, failure: VerificationResult | None) -> Flow:
    # 返回 NORMAL / CACHE / EXCEPTION / HUMAN
    # 规则（按序短路）：
    if failure is not None and failure.level == STRONG and not failure.status == PASSED:
        return HUMAN if failure.retries >= 2 else EXCEPTION
    if failure is not None:                        # 弱校验失败
        return EXCEPTION
    if cache_hit and _light_check(state):          # 缓存命中 + 轻量校验
        return CACHE
    if diff is None or diff.significant:           # 状态显著变化 / 首步
        return NORMAL
    return NORMAL
```
执行流选择是纯函数（可单测）；切换记录进 trace（`flow_switch` span）。
