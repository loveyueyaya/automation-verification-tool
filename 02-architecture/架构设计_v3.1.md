## 二、select_flow 5 流（补 LLM 流）

v3 只列 4 个流（NORMAL/CACHE/EXCEPTION/HUMAN）；P1 实际实现为 **5 流**（contracts/flow.py）：

| 流 | 触发条件（按序短路） |
|---|---|
| HUMAN | failure 非空 且 level==STRONG 且 retries >= 2 |
| EXCEPTION | failure 非空（STRONG 但 retries<2，或弱校验失败） |
| CACHE | cache_hit 且 light_check 通过 且 exact_repeat（同 state_hash + 同 target_element_id + 同 action） |
| NORMAL | cache_hit 且 light_check 通过 但非 exact_repeat |
| LLM | diff 为空或 significant（首步 / 状态显著变化） |

规则顺序（纯函数，可单测）：
1. failure 非空 → HUMAN / EXCEPTION
2. cache_hit 且 light_check → CACHE / NORMAL
3. diff 为空或 significant → **LLM**
4. 其他 → NORMAL

`light_check` 定义：目标元素指纹仍在（elements 含 target_element_id）+ 窗口 rect 未变（对比 baseline_rect）。

## 三、元素 id 双用途（独立函数）

`elem_s:{semantic}_p:{control_path}_h:{handle}`，**空段一律写 `none`**（禁止双下划线自造空段记号）：

| 用途 | 函数 | 优先级 |
|---|---|---|
| 定位用 | `resolve_for_action(eid)` | L1 handle > L2 control_path > L3 semantic |
| 缓存键用 | `resolve_for_cache(eid)` | L3 semantic > L2 control_path > L1 handle |

示例：`elem_s:a3f2_p:none_h:0x1A2B`（仅 handle）合法；`elem_s:none_p:Window/Edit[1]_h:none`（仅路径）合法。

## 四、state_hash 的 target_hint 参数含义

`state_hash(snapshot, target_hint=None)`：

- **target_hint = 当前任务的目标元素 id**，用于圈定参与哈希的关键元素范围
- 非空：取 `id == target_hint` 的元素 + 所有输入框（每类上限 8）
- 为空：取全部 `button / input / text_area`（每类上限 8）
- 位置量化：2% 网格（窗口宽高 50 格）；文本规范化：去首尾空白 / 全角→半角 / 小写
- **不参与**：ocr 结果、visual_features、原始坐标精确值、trace 元数据

## 五、跨进程 trace 时间偏移说明

规格（v3 第四节落地版）不变，补充**报告展示规则**：

> 子进程启动延迟 N ms 已计入偏移。

- `offset = t_parent0(spawn 前) - t_child0(子进程启动)`，span 的 `ts = time.time() + offset`（归一父进程时钟）
- offset 内含子进程启动延迟**属正常**，报告展示时加上述一行说明，**避免误判卡顿**
- 断链检测：孤儿 span 标黄 + "跨进程断链"告警
